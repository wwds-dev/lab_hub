  - `lab_hub/` — "Lab Hub.app", the front door for the rest. Tabs: **Apps** (the umbrella
    apps — Sentinel, Imprint, SONAR, Provisio, SYNDUSTRYX — each started as its own process, from
    `/Applications` when installed and from the checkout's own `.venv` otherwise; cards
    show **Running** from a `ps` snapshot, the build they would launch, and *Bring to
    front* instead of a duplicate launch. A tile also reports an app's windowless
    background copy separately (`ExternalApp.service`, SONAR's engine) — reported, never
    counted as the app being open. **Match a running app on both its bundle path and its checkout's entry script**
    (`running_markers()`, either counts): an installed bundle is not reliably the process
    that keeps running — Sentinel's execs the project's python and exits — and matching the
    bundle alone reported a running app as *Did not start* indefinitely. The checkout half
    of that pair is only as good as `ExternalApp.project`, a directory name listed in
    `lab_hub/apps.toml` (the app list, re-read on Refresh; the frozen app prefers the copy in the lab checkout) and only corrected on the next Lab Hub build — so when the Sentinel
    folder was renamed on 2026-10-06 the installed v2.049 went looking for `sentinel_fork`,
    lost its checkout marker, fell back to the bundle alone and reported the identical bug
    on 2026-10-07. **`source_dir()` therefore falls back to the checkout the bundle itself
    records** (`Contents/Resources/project_root.txt`, written by the project's own
    installer and right the day the folder moves); the configured lab folder still wins,
    so Settings keeps deciding where projects are looked for. And **never say *Did not
    start* about a launch nothing could have watched** (`launch_is_observable()`): a stub
    bundle that execs and exits, with no checkout to watch instead, leaves a successful
    launch and a dead one looking identical, so the tile says *Started* and admits it
    cannot tell. `main.py --selftest` fails the build when a registered `project` no
    longer exists but the bundle's record does — the stale name is caught at build time
    rather than on a tile. Skip command
    lines carrying a `NO_WINDOW_FLAGS` flag (`--headless`) and match **per line**, not
    across the whole `ps` snapshot: SONAR's launchd agent runs `main.py --headless` around
    the clock and otherwise made that tile read *Running* permanently. `--background` is
    deliberately not such a flag — it is the whole app with its window hidden, which is how
    Lab Hub starts Backup Control Center and git_autosync, and they can be raised. Note
    that *Running* legitimately outlives the window for the apps that hide to the menu bar
    on close (SONAR, Lab Hub itself), so a tile saying *Running* after you closed the
    window is usually right. *Did not start* is
    a notice about one launch, not a state of the app: it expires, and Re-check clears it. Whether an app *can* start is answered before the button is pressed
    (`launcher.readiness()` — a checkout with no venv and no `python3`, or a bundle that
    kept its directory but lost its executable, both disable Launch and say why); whether
    it *did* start is answered after, because `open` hands back no exit code for a bundle
    — the tile waits at *Starting…* and turns to *Did not start* if the process never
    appears. Read a bundle's binary from `CFBundleExecutable`, never from the app's name:
    every app's executable is now named after the app (Sentinel's was `applet`, then
    `SentinelLauncher`, before it became `Sentinel` on 2026-10-07 — check, do not assume;
    a live launcher is told from a frozen build by `Contents/Resources/project_root.txt`,
    not by the executable's name; the app was renamed from
    Sentinel Fork on 2026-09-12 and the folder, the repo and the remote followed on
    2026-10-06, so `sentinel` is now the name at every level). **Agents and sub-modules get no tile and no menu bar entry**: Tunnel and Bug
    Spray belong to Sentinel, the video pipeline to Imprint, macro and Playmaker to
    SONAR, and each is reached from its own app. Two doors to the same feature gives you a
    standalone window that knows nothing about the session that should own it — the
    nested-companion rows tried in Sep 2026 were removed for the same reason. Two tiles
    were added 2026-10-07. **Provisio** launches its native app (`/Applications/Provisio.app`,
    else the checkout's `main.py`; demo and real workspaces, `provisio/docs/DESKTOP.md`) —
    it was a browser-mode *web app* tile for a few hours that day, and must not start that
    server any more, because vinext allows one dev server per checkout. The web-app support
    (`ExternalApp.url`, Stop, the longer start wait) stays in the `launcher` package, unused.
    Headroom, its `engine/`, gets no tile. **SYNDUSTRYX** (formerly "SYNDUSTRYX") — the Antfarm workstation,
    named by the owner 2026-10-09 (clearance open); the tile shows the Info.plist release — opens the bundle its builder leaves in `dist/` (`bundle_dir`, tile
    state *Built*) and never runs its checkout (`runs_from_source=False`: `server.py` is
    its engine on port 8765, which the Lab Project Monitor holds)),
    **Websites** (altmerch.store, bookadatewithme.com — a non-blocking `HEAD` per site, so
    a tile says *Online* / *Error 404* / *Unreachable*; registered in `lab_hub/sites.py`),
    **Dashboards** (every entry in `dashboard_catalog.json`, the same file the Monitor's
    Dashboards section reads, re-read when it changes — never copied into Lab Hub; the
    menu bar has a submenu for each of these two tabs),
    **Backup and Sync** (Backup Control Center,
    git_autosync — spelled "and", because Qt reads `&` in a tab label as a mnemonic and
    renders it "Backup _Sync"; neither has a launchpad tile, so this tab carries its own
    **Check builds** / **Update now** scoped to the two, like Backstage's card),
    **Tools** (navigation is a left sidebar since 2026-10-12, Graphite dark / Paper light, switchable in Settings; opens on *All tools*, every tool as a tile — added 2026-10-07; then Convert
    Textfiles, Narrator, Prepare Images — all
    embedded — plus Unblock Tracker and Backstage as launch cards; Backstage lives in
    `launcher.TOOLS_ONLY_APPS` (`lab_hub/apps.toml`), which the menu bar does not read), **Settings**. Ebook Converter has no
    tile on purpose: the embedded Convert Textfiles tab already does that job. Runs as a **single instance** guarded
    by a local socket, with a **menu bar item**; closing the window hides it rather than
    quitting — and so does **quitting from the Dock, or ⌘Q**, since the Dock icon exists
    only while a window does, so Quit there means "off my screen". macOS routes both
    through `applicationShouldTerminate:`, which Qt delivers as a `QEvent.Quit` to the
    application object; `_QuitGuard` refuses it with `event.ignore()` — consuming the
    event by returning `True` does *not* refuse it, because a `QEvent` starts out
    accepted and filtering one leaves that flag set. The menu bar's **Quit Lab Hub** is
    the only real exit, and bypasses the event by calling `QApplication.quit()`; keep the
    test that runs a real event loop to prove it, or the next change here ships an app
    nobody can quit. The **Dock icon follows the window**: the bundle declares
    `LSUIElement` so it starts as a menu bar accessory, and `ui/dock.py` promotes it to
    `Regular` — plus `activateIgnoringOtherApps:`, without which the window is created
    behind everything and looks like no window at all — only when a window is shown.
    Verify with `main.py --selftest`, which reads the policy from inside the process.
    `lsappinfo`'s `ApplicationType` does track it too (`Foreground` with the window up,
    `UIElement` once hidden, against one running pid) — this file used to claim it only
    reported the declared `Info.plist` type, which was wrong; what it could not show was
    a switch that was not happening. **Start at login** is a LaunchAgent (`com.netrunner3000.labhub.login`) running
    `open -a … --args --background`, because a login item cannot pass arguments and a menu bar
    app should start into the menu bar, not open a window. `tools/convert/` is a **vendored
    copy** of `toolbox/convert_epub/ebook_converter/` (copied, not imported — keep the two
    in step by hand; as of this reorg they have drifted — `calibre.py`, `formats.py`,
    `jobs.py`, `runner.py` all differ and the toolbox copy has a `config.py` the vendored
    one lacks — reconcile before trusting either blindly). `pytest` covers the window
    lifecycle and the Qt-free tools; `main.py --selftest` covers what only a build can
    break — including a real `QApplication` started under **every** registered app's own
    venv with the scrubbed child environment, which is the only way the Qt-plugin
    inheritance crash is catchable. It probes each interpreter rather than running the
    apps: six windows per build would not survive being run, and the abort happens inside
    `QApplication()` anyway.
